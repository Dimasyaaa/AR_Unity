# Модуль инвентаризации

Документ описывает путь данных от QR-кода до отчёта в админ-панели.

## Пользовательский сценарий

1. Сотрудник входит в приложение и сканирует QR-код шкафа.
2. В `SampleScene` размещает нужные AR-карточки: калькулятор, вид шкафа или чек-лист. Каждая карточка может быть оверлеем или объектом в пространстве.
3. `CabinetViewCard` получает изображения листов шкафа по QR-коду и позволяет переключать их.
4. `InventoryChecklistCard` получает список предметов. Для каждого пункта сотрудник отмечает **«Есть»** или **«Нет»**. Список прокручивается экранными кнопками вверх и вниз; основные действия также доступны голосом.
5. При завершении проверки открывается форма отчёта. В ней можно добавить несколько фотографий текущей сцены, записать голосовой комментарий, прослушать его и отправить отчёт.
6. При отсутствии соединения данные остаются в локальной очереди. После восстановления связи сотрудник запускает синхронизацию по Wi-Fi или USB.
7. Администратор открывает раздел «Инвентаризации» → «Подробнее», чтобы посмотреть сотрудника, время, ответы по пунктам, фотографии и голосовое сообщение.

Калькулятор отдельно записывает результат в журнал как действие `calc`.

## QR-код

QR содержит обычный текстовый payload. Важно, чтобы строка в QR точно совпадала со значением `qr_codes.code`, которое активно и привязано к настроенному шкафу. URL можно использовать только если в базе именно URL записан как код.

В тестовом SQL-файле `Backend/Database/002_demo_cabinet_data.sql` подготовлены значения `DEMO-CABINET-001` и `DEMO-CABINET-002`. Unity Editor сейчас эмулирует `test2` — оно должно быть в загруженной локальной или серверной базе. Для устройства сгенерируйте изображение QR по коду из актуального раздела «QR-коды» админки.

## Где хранятся данные

| Таблица PostgreSQL | Назначение |
|---|---|
| `qr_codes` | Значение и описание QR-кода |
| `cabinet_profiles` | Связь шкафа с QR и его основными данными |
| `cabinet_photos` | Фотографии страниц шкафа |
| `cabinet_checklist_items` | Текущий перечень предметов шкафа |
| `inventory_runs` | Завершённые проверки, автор и время |
| `inventory_run_items` | Ответ по каждому предмету на момент проверки |
| `inventory_run_media` и `inventory_run_photos` | Голосовое сообщение и фотографии отчёта |

SQLite на устройстве содержит локальный справочник, пользовательские действия и незавершённые отправки. Файл `Assets/StreamingAssets/InventoryDatabase/inventory.db` — начальная версия справочника, включаемая в сборку. При запуске приложение копирует его в постоянное хранилище устройства; экспортированный справочник обновляет локальные справочные таблицы, сохраняя локальные действия и очередь.

## Изменение справочника

1. В админ-панели создайте или выберите активный QR-код.
2. В разделе «Шкафы» привяжите QR, задайте название, загрузите фотографии листов и внесите каждый пункт списка отдельной строкой.
3. Сохраните изменения и проверьте результат через API или приложение.
4. Чтобы новая версия справочника была доступна без сети в следующей сборке, откройте Unity и выберите **Tools → Database → Export PostgreSQL to SQLite**.

Удаление настроенного шкафа выполняется каскадно через серверный API: вместе с ним удаляются связанные QR-код, пункты, фотографии и история инвентаризаций. Для необратимого изменения базы перед удалением делайте резервную копию PostgreSQL.

## PostgreSQL и миграции

SQL-файлы находятся в `Backend/Database`. Это исходные миграции и тестовые seed-данные, а не рабочая копия базы. Сервер сам их не запускает — применяй изменения к PostgreSQL вручную и в порядке номеров.

- `001_cabinet_inventory.sql` создаёт основу данных шкафов и инвентаризаций.
- `002_demo_cabinet_data.sql` добавляет демонстрационные шкафы и предметы; используй только в тестовой базе.
- `003`–`008` добавляют последующие связи, страницы фото, журнал калькулятора и медиа отчётов.

Для просмотра фото и голосовых вложений в отчётах на базе должны быть применены актуальные миграции, включая `007_inventory_report_media.sql` и `008_inventory_run_photos.sql`.

## Основные маршруты API

| Метод и адрес | Назначение |
|---|---|
| `GET /api/health` | Проверка доступности сервера |
| `GET /api/inventory/cabinets?qrCode=...` | Данные шкафа и список предметов по QR |
| `GET /api/inventory/cabinet-photo?qrCode=...&pageNumber=1` | Фото страницы шкафа |
| `POST /api/sync/inventory-runs` | Передача завершённых проверок и вложений |
| `GET /api/admin/inventory/runs` | Список отчётов в админке |
| `GET /api/admin/inventory/runs/{id}` | Подробности отчёта и ответы по пунктам |
| `GET /api/admin/inventory/runs/{id}/media/photo/{index}` | Фотография отчёта |
| `GET /api/admin/inventory/runs/{id}/media/{kind}` | Голосовое сообщение отчёта |

Swagger опубликован на `/swagger`. Админ-панель открывается на `/admin`.

## Настройка локального API

Сервер слушает порт `8000`. Для подключения к PostgreSQL ему нужна строка подключения через переменную среды `AR_INVENTORY_DB_CONNECTION` либо `ConnectionStrings:DefaultConnection` в локальном `appsettings.Development.json`. Не добавляй файл с паролем в Git.

Unity хранит адреса Wi-Fi и USB-синхронизации в `Assets/App/Scripts/Local/SyncManager.cs`. Для работы телефона серверный компьютер и устройство должны быть доступны друг другу в локальной сети; `localhost` телефона указывает на сам телефон, а не на компьютер.
