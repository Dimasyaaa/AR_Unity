# Инвентаризация коробок

## Рабочий сценарий

1. Сотрудник входит в приложение и открывает экран назначенной инвентаризации.
2. На главной сцене выбирает **«Начать инвентаризацию»**. Назначенные QR-коды доступны по одному, а приложение показывает прогресс.
3. После сканирования QR открывается `SampleScene`. Данные коробки загружаются из локального кэша или API.
4. Сотрудник заполняет пункты **«Есть / Нет»**, указывает фактическое количество, при необходимости смотрит фотографии и 3D-модель содержимого.
5. Он делает фотоотчёт, при желании добавляет голосовую или текстовую заметку и завершает проверку коробки.
6. После завершения всех коробок Unity показывает сводную таблицу. Сервер формирует ту же сводку для просмотра и скачивания в Excel.

## Данные коробки

QR-код содержит обычный текст. Его значение должно совпадать с активным `qr_codes.code` в базе. Сам QR не хранит фото или GLB: API использует код, чтобы найти коробку и вернуть её данные.

Администратор настраивает название, перечень содержимого, ожидаемое количество, любое число изображений и необязательную GLB-модель. Демонстрационные коды `DEMO-BOX-001`…`DEMO-BOX-005` и позиции находятся в `Backend/Database/demo_boxes.sql`.

## Структура PostgreSQL

Актуальное описание таблиц, связей, подготовки новой базы и обновления существующей находится в [`Backend/Database/README.md`](../Backend/Database/README.md).

Вкратце:

- `boxes` связывает карточку коробки с QR-кодом и необязательной GLB-моделью;
- `box_items` хранит текущие позиции и ожидаемое количество;
- `box_photos` содержит все изображения коробки, по одному изображению в строке;
- `inventory_batches` и `inventory_batch_boxes` хранят назначение сотруднику;
- `inventory_runs` и `inventory_run_items` хранят проверки и ответы на момент их выполнения;
- `inventory_run_attachments` хранит фото и необязательную голосовую запись отчёта;
- `inventory_sessions` хранит общий журнал приложения.

Локальная SQLite-база — это кэш для входа, данных коробок и офлайн-очереди. Она обновляется через **Tools → Database → Export PostgreSQL to SQLite**. Серверная схема PostgreSQL и локальные таблицы имеют разные задачи; экспортёр переводит серверные данные в формат локального кэша, чтобы не терять офлайн-совместимость.

## REST API

| Маршрут | Назначение |
| --- | --- |
| `GET /api/inventory/boxes?qrCode=...` | Карточка коробки, позиции, фотографии и наличие GLB. |
| `GET /api/inventory/box-photo?qrCode=...&pageNumber=...` | Изображение содержимого коробки. |
| `GET /api/inventory/box-model?qrCode=...` | GLB-модель коробки, если она загружена. |
| `GET /api/inventory/assignments/{userId}/overview` | Активное назначение и история сотрудника. |
| `POST /api/sync/inventory-runs` | Синхронизация результатов проверок и вложений. |
| `GET /api/admin/inventory/batches/{id}/excel` | Скачать сводную таблицу общей проверки в формате `.xlsx`. |

Старые маршруты `/api/inventory/cabinets` и `/api/inventory/cabinet-photo` оставлены только для уже собранных версий приложения. Новая Unity-сборка использует маршруты `/boxes` и `/box-photo`.

## Настройка и удаление коробки

В админ-панели откройте **Коробки**, выберите QR-код, настройте позиции, фотографии и при необходимости модель. Назначение создаётся во вкладке **Инвентаризации** и связывает выбранные QR-коды с сотрудником.

Удаление коробки выполняется через API одной транзакцией: удаляются QR-код, текущее содержимое и история этой коробки с её вложениями. Перед ручными изменениями PostgreSQL сделайте резервный `pg_dump`.
