# Карта проекта Unity

## Как читать папки

В `Assets` лежат файлы приложения и ресурсы, которые Unity или пакеты ожидают по специальным путям. Поэтому не каждую папку рядом с `App` следует переносить внутрь неё.

```text
AR_Unity/
├── Assets/
│   ├── App/                         # Собственная часть приложения
│   │   ├── DatabaseTools/Editor/    # Окно экспорта PostgreSQL → SQLite
│   │   ├── Content/                 # Визуальные материалы приложения
│   │   │   ├── Cards/               # Переиспользуемые AR-карточки
│   │   │   ├── Branding/            # Логотипы Норникеля
│   │   │   └── UI/Icons/            # Иконки экранов и кнопок
│   │   ├── Scenes/                  # LoginScene, StartScene, SampleScene
│   │   └── Scripts/                 # Код приложения по функциям
│   ├── StreamingAssets/             # Зарезервированная Unity папка для файлов сборки
│   │   └── InventoryDatabase/       # Начальная SQLite база
│   ├── Settings/                    # Активные настройки URP
│   ├── Plugins/                     # Android QR/WebView и сборочные расширения
│   ├── MobileARTemplateAssets/      # Ресурсы мобильного AR шаблона
│   ├── Samples/                     # Примеры XR Interaction Toolkit
│   ├── NuGet/                       # Менеджер NuGet для Unity
│   ├── Packages/                    # Сторонние .NET библиотеки, загруженные NuGet
│   ├── Resources/                   # Изображения, загружаемые кодом по имени
│   ├── TextMesh Pro/                # Ресурсы текстового компонента TMP
│   ├── XR/ и XRI/                   # Настройки AR/XR и Interaction Toolkit
│   └── [другие папки пакетов]       # Ресурсы Unity и сторонних зависимостей
├── Packages/                        # Манифест UPM-пакетов Unity и lock-файл
├── ProjectSettings/                 # Настройки проекта и сборки
├── Backend/                         # Сервер API и административная панель
├── Builds/                          # Локально сохранённые APK; не исходники и не Git
├── docs/                            # Документация и скриншоты
├── README.md                        # Обзор проекта и запуск
└── AR_Unity.slnx                    # IDE-решение; Unity генерирует C#-проекты рядом
```

## Что в корне является исходниками, а что — рабочими файлами

В проекте достаточно хранить `Assets`, `Packages`, `ProjectSettings`, `Backend`, `docs`, `README.md`, `.gitignore` и `.vsconfig`. Файл `AR_Unity.slnx` оставлен как основное решение для IDE. Файлы `*.csproj` генерируются Unity для C#-редакторов; они нужны для удобного перехода по коду, но не являются исходниками приложения.

Следующие каталоги Unity и инструментов создаются автоматически и не должны попадать в Git: `Library`, `Temp`, `Logs`, `UserSettings`, `.vs`, `.utmp`, `build`, `Backend/bin`, `Backend/obj` и `*_BurstDebugInformation_DoNotShip`. Их можно пересоздать из исходников. `Builds` предназначена только для локальных сборок и архивов APK; содержимое также исключено из Git. Например, старый `bdtest.apk` сохранён в `Builds/PreviousTestBuilds`, а не лежит рядом с исходниками.

Не удаляй `Assets`, `Packages` или `ProjectSettings`: в них находятся сцены, код, ресурсы, версии пакетов и настройки Unity. `Backend` — исходный код сервера, а `docs` — документация и иллюстрации проекта. `Library`, `Temp` и `Logs` пока оставлены на диске, пока Unity открыт; удалять их для упорядочивания корня не требуется.

## Назначение и правила перемещения

| Путь | Для чего нужен | Рекомендация |
|---|---|---|
| `Assets/App` | Сцены и собственный код приложения | Основное место для новых функций приложения |
| `Assets/App/Content` | Собственные визуальные ресурсы и готовые карточки | Добавлять новые карточки и графику приложения сюда; не в папки шаблонов |
| `Assets/App/Content/Cards` | `CalculatorCard`, `ProductInfoCard`, `WebCard` | Дублировать подходящую карточку, менять её внешний вид и поведение отдельно |
| `Assets/App/Content/Branding` | Логотип и знак Норникеля | Здесь хранить фирменную графику приложения |
| `Assets/App/Content/UI/Icons` | Иконки кнопок интерфейса | Здесь хранить собственные иконки, используемые в меню/сценах |
| `Assets/StreamingAssets` | Файлы, которые Unity копирует в сборку без импорта | Оставить имя и расположение в `Assets`; база уже выделена в `InventoryDatabase` |
| `Assets/App/DatabaseTools/Editor` | Инструмент экспорта базы, работающий только в редакторе | Имя `Editor` оставить: Unity использует эту специальную папку для редакторского кода |
| `Assets/Settings` | URP Global Settings, Render Pipeline и Renderer | Не удалять: pipeline и renderer назначены в `ProjectSettings/GraphicsSettings.asset` и `QualitySettings.asset` |
| `Assets/Plugins/Android` | Kotlin QR-модуль, Gradle-шаблоны и Android-библиотеки | Не переносить без отдельной проверки Android-сборки |
| `Assets/Plugins/Editor` | Дополнения Unity Editor для WebView-плагина | Оставить под специальным именем `Editor` |
| `Assets/Packages` | .NET DLL-зависимости SQLite, PostgreSQL и других библиотек | Это не каталог UPM-пакетов; не смешивать с корневым `Packages/` |
| `Assets/NuGet` | Менеджер NuGet for Unity, который управляет .NET-библиотеками | Сохранить, пока проект использует эти библиотеки |
| `Assets/Resources` | Файлы, которые код получает через `Resources.Load` | Оставить до проверки всех строковых обращений в коде |
| `Assets/MobileARTemplateAssets` | AR-префабы, UI, шейдеры и скрипты шаблона | Сохранить используемые ресурсы: `SampleScene` ссылается на префабы и скрипты |
| `Assets/Samples/XR Interaction Toolkit` | Импортированные примеры XRI | Не удалять целиком: `SampleScene` прямо ссылается на AR Starter Assets и XR-префабы |
| `Assets/TextMesh Pro`, `Assets/XR`, `Assets/XRI` | Ресурсы и конфигурация Unity/TMP/XR | Системные зависимости проекта; проверять ссылки до переносов |
| `Packages/` | Манифест и версии UPM-пакетов | Управлять через Package Manager, не складывать сюда DLL из NuGet |

## Что проверено сейчас

- `Assets/Settings` содержит три URP-ассета; pipeline и renderer используются настройками графики и уровней качества. Удалять каталог нельзя.
- `SampleScene` напрямую использует Mobile AR Template и XR Interaction Toolkit: например, `ARFeatheredOcclusionPlane`, варианты карточек, `XR Origin (AR Rig)`, контроллер меню и input actions.
- `Assets/MobileARTemplateAssets/Tutorial` содержит материалы приветственного туториала шаблона. Ссылок на них из сцен приложения не найдено; это кандидат на отдельную очистку, но сейчас папка оставлена.
- В `Assets/Packages` находятся NuGet-библиотеки для SQLite, PostgreSQL и сетевой части; это сторонние зависимости приложения, не «папка базы данных».
- Примеры XRI лежат в каталоге `3.3.0`, а `Packages/manifest.json` запрашивает XRI `3.5.0`. Это не доказывает поломку, но перед обновлением или удалением sample-файлов стоит отдельно сверить совместимость.
- Собственные AR-карточки и фирменные изображения отделены от `MobileARTemplateAssets` и размещены в `Assets/App/Content`; исходные `.meta` сохранены, GUID сцен не менялись.
- Из `MobileARTemplateAssets/Prefabs` удалены пять неиспользуемых вариантов фигур (Arch, Cylinder, Debug Cube, Pyramid, Torus): GUID-поиск не нашёл ссылок на них в сценах, префабах или настройках. Используемые `CubeVariant` и `WedgeVariant` оставлены.
- Иконки `icon_info.png` и `icon_view.png` уже находятся в `Assets/App/Content/UI/Icons`; пока они не привязаны к компонентам сцен.
- Карточки построены на демонстрационном префабе XRI `Debug Cube`. Это зависимость шаблона; не удалять этот образец, пока карточки не будут отвязаны от его базового префаба.

## Как добавить элементы приложения

### Новая кнопка в главном меню

В сцене `StartScene` открой `Canvas → Menu Buttons`, дублируй наиболее похожую кнопку и переименуй её понятно. Измени надпись и цвет/иконку в Inspector. Раскладку основных кнопок по портрету и альбомной ориентации выполняет `ResponsiveMainMenu` на Canvas. Для новой кнопки нужно добавить её имя в массив раскладки этого скрипта и определить её действие в менеджере меню; иначе кнопка будет видна, но ничего не сделает. Заголовок, логотип и справка лежат в `Canvas → Header`.

В сцене `SampleScene` AR-кнопки и панели находятся в группе `UI`. Для новой AR-карточки дублируй близкий по назначению префаб из `Assets/App/Content/Cards`, создай кнопку и назначь её `ARCardButtonHook → Card Prefab`. Обработчик сам найдёт префаб в `ObjectSpawner` или добавит его в список, поэтому вручную добавлять объект и считать индекс не нужно. Существующие специальные Web- и информационная кнопки также используют прямые ссылки на префабы; обработчик Web-кнопки сохраняет выбор между оверлеем и AR-объектом.

### Где менять внешний вид и логику

- Внешний вид и содержимое карточек — `Assets/App/Content/Cards`.
- Логотипы и изображения бренда — `Assets/App/Content/Branding`.
- Иконки — `Assets/App/Content/UI/Icons`.
- Поведение карточек находится рядом по назначению в `Assets/App/Scripts/AR/Calculator`, `AR/Cards` и `AR/Web`.
- `ARCardButtonHook` — общий обработчик кнопки для новой AR-карточки; `ARCardSpawnUtility` автоматически выбирает или регистрирует Prefab у `ObjectSpawner`.
- Экранные объекты конкретной сцены редактируются в Hierarchy соответствующей сцены; переиспользуемые объекты сохраняются как Prefab в `Assets/App/Content`.
- Для любого переноса или переименования ассета оставляй его `.meta` рядом — так Unity сохраняет ссылки сцен.

## Правило безопасной уборки

Перед удалением или переименованием Unity-ресурса проверять GUID-ссылки в сценах, префабах, материалах, настройках проекта и коде. Перемещать Unity-ресурсы через редактор либо переносить вместе с `.meta`: GUID в `.meta` сохраняет ссылки сцен на компонент или ассет.
